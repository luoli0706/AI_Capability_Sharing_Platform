# AI 能力共享平台（ASCP）P0–P2 分级开发方案

> 本文档依据 [系统设计方案.md](file:///C:/Users/12907/Desktop/cur/docs/毕业设计/AI_Capability_Sharing_Platform/docs/系统设计方案.md) 制定，将全平台开发任务按优先级拆分为 **P0（核心闭环 MVP）**、**P1（完整业务与权限治理）**、**P2（统计看板、高可用网关与 CI/CD 工程化）** 三个阶段，确保毕业设计按期高质量交付。

## 总览：P0–P2 阶段定位

| 优先级 | 阶段定位 | 核心目标 | 建议周期 |
| :--- | :--- | :--- | :--- |
| **P0** | **核心底座与最小可用闭环（MVP）** | 跑通“用户登录 → 业务域管理 → 四类 AI 资产创建/发布 → 能力广场检索与基础调用”主链路 | 第 1~4 周 |
| **P1** | **完整业务治理与审批闭环** | 补齐知识库切片检索、版本快照回滚、多级审批流、API Key 鉴权拦截与调用审计日志 | 第 5~8 周 |
| **P2** | **可观测性、网关调优与 CI/CD** | 完成 ECharts 数据统计看板、Nginx 限流/负载均衡验证、Docker Compose 与 CI/CD 自动部署回滚 | 第 9~12 周 |

## 1. P0 开发方案：核心底座与最小可用闭环（MVP）

### 1.1 目标与范围
完成系统基础设施、账号 RBAC 体系、业务域隔离骨架以及四类 AI 资产的 CRUD 与基础发布调用，使平台具备基本可演示的端到端流程。

### 1.2 后端开发清单（Go Echo）
1. **工程底座与数据库连接**：
   - 接入 GORM + MySQL 8.0，执行 [001_init.sql](file:///C:/Users/12907/Desktop/cur/docs/毕业设计/AI_Capability_Sharing_Platform/src/backend/migrations/001_init.sql) 初始化表结构。
   - 封装统一响应结构（`response.Success` / `response.Error`）、Zap 结构化日志中间件、Panic 恢复中间件。
2. **账号与 JWT 鉴权模块**：
   - 实现用户注册（`POST /api/v1/auth/register`）、登录（`POST /api/v1/auth/login`）、登出（`POST /api/v1/auth/logout`，递增 `sys_user.token_version`）。
   - 实现密码修改（`PUT /api/v1/user/password`）与 BCrypt 加密校验。
   - 实现 `AuthMiddleware`：解析 JWT 并校验 `token_version` 与用户启用状态，注入当前用户与角色上下文。
3. **业务域基础管理**：
   - 实现域创建、域列表查询、域成员添加与角色设置（`GET/POST /api/v1/domains`、`POST /api/v1/domains/:id/members`）。
4. **AI 资产基础管理（四类资产统一主表 + 扩展表）**：
   - 实现资产列表检索（支持按 `asset_type`、`domain_id`、`keyword`、`status` 过滤）与详情查询（`GET /api/v1/assets`、`GET /api/v1/assets/:id`）。
   - 实现 MCP、Skill、Agent、知识库四类资产的新增与编辑（`POST /api/v1/assets`、`PUT /api/v1/assets/:id`）。
   - 实现简化版发布与下线（`POST /api/v1/assets/:id/publish`、`POST /api/v1/assets/:id/offline`）。
5. **基础个人中心**：
   - 个人信息查询与修改（`GET /api/v1/user/profile`）、我创建的资产列表（`GET /api/v1/user/assets`）。

### 1.3 前端开发清单（Vue 3）
1. **全局布局与认证页**：
   - 登录页（`/login`）、注册页（`/register`）及 Pinia 用户状态持久化。
   - 主工作台 Layout（左侧导航菜单 + 顶部用户信息与登出按钮）及路由守卫。
2. **能力广场（`/marketplace`）**：
   - 资产卡片列表、类型筛选 Tab（全部 / MCP / Skill / Agent / 知识库）、关键词搜索、资产详情抽屉。
3. **资产工作台（`/assets`）**：
   - 四类资产创建/编辑表单与弹窗、状态标签展示、发布/下线操作按钮。
4. **个人中心基础页（`/profile`）**：
   - 个人资料展示、修改密码表单、“我的资产”列表。

### 1.4 P0 验收标准
- 新用户可注册、登录并获取有效 JWT；登出后旧 JWT 立即失效。
- 管理员或研发人员可创建业务域并管理域成员。
- 可创建 MCP、Skill、Agent、知识库四类资产并切换为已发布状态，在能力广场中被检索和查看。

## 2. P1 开发方案：完整业务治理、知识库与多级审批闭环

### 2.1 目标与范围
围绕 [base-需求.txt](file:///C:/Users/12907/Desktop/cur/docs/毕业设计/AI_Capability_Sharing_Platform/docs/base-需求.txt) 中的核心治理痛点，落地**知识库文档切片检索**、**资产版本控制**、**多级审批流**、**统一调用鉴权拦截**与**审计日志**，实现全链路数字化闭环。

### 2.2 后端开发清单（Go Echo）
1. **知识库文档上传与异步切片入库**：
   - 实现文档上传接口（`POST /api/v1/kb/:id/documents`），保存原始文件至本地存储目录，写入 `kb_document`（`parse_status = pending`）。
   - 启动后端异步 Goroutine 工作池，解析 TXT/Markdown/PDF 文本，按 `chunk_size` 与 `chunk_overlap` 执行滑动窗口切片并写入 `kb_chunk`。
   - 实现文档列表/删除接口及基于 MySQL `FULLTEXT` / 关键词匹配的检索召回接口（`POST /api/v1/kb/:id/search`）。
2. **AI 资产版本快照与 MCP 探测**：
   - 每次提交发布时自动生成 `ai_asset_version` 完整 JSON 快照与语义化版本号，支持版本列表查看与一键回滚（`GET /api/v1/assets/:id/versions`、`POST /api/v1/assets/:id/rollback`）。
   - 实现 MCP Server 连通性健康检查与 Tools 清单探测同步（`POST /api/v1/assets/:id/mcp/sync-tools`、`health-check`）。
3. **权限订阅与多级审批流**：
   - 公开/域内可见资产支持一键订阅（`POST /api/v1/assets/:id/subscribe`），写入 `asset_permission`。
   - 私有或跨域资产支持发起权限申请（`POST /api/v1/approvals`），自动生成多级审批节点（一级：资产负责人；二级：目标域管理员）。
   - 实现“我的申请”、“待我审批”与审批处理接口（`POST /api/v1/approvals/:id/handle`），二级审批通过后自动生效 `asset_permission`。
4. **API Key 管理与统一调用鉴权代理**：
   - 实现个人中心 API Key 生成（返回明文一次、库内存 SHA-256 哈希）与吊销（`POST/DELETE /api/v1/user/api-keys`）。
   - 实现 `AssetGuardMiddleware`：对 `/api/v1/invoke/*` 请求统一校验 `JWT` 或 `X-API-Key`、资产发布态、域隔离与 `asset_permission` 有效期。
   - 实现 MCP、Agent、知识库统一代理调用接口，并记录调用耗时、状态码与结果至 `asset_invoke_log`（同时累加 `ai_asset.invoke_count`）。

### 2.3 前端开发清单（Vue 3）
1. **私有知识库模块（`/knowledge-bases`）**：
   - 文档拖拽上传、解析状态轮询展示、切片预览抽屉、可见范围配置、在线检索召回测试面板。
2. **版本管理与 Agent 编排增强**：
   - Agent 编辑页支持可视化勾选已发布的 MCP、Skill 与知识库进行绑定。
   - 资产版本历史抽屉，支持查看变更日志与回滚确认。
3. **域与审批中心（`/governance`）**：
   - 业务域成员管理界面；审批工作台（“待我审批”、“我发起的申请”、“已处理”三 Tab），展示多级审批进度时间轴。
4. **个人中心完善（`/profile`）**：
   - API Key 创建/复制/吊销管理面板；个人调用记录审计日志表格（支持按资产、状态筛选）。

### 2.4 P1 验收标准
- 上传知识库文档后可自动完成切片入库，并能通过检索接口召回对应切片内容。
- 资产修改并重新发布后可追溯历史版本并成功回滚。
- 跨域申请受控资产时，需依次经过资产负责人与域管理员两级审批；审批通过前调用被拦截（返回 403），通过后可使用 JWT 或 API Key 成功调用并生成 `asset_invoke_log`。

## 3. P2 开发方案：统计看板、Nginx 网关调优与 CI/CD 工程化

### 3.1 目标与范围
完善平台的数据可观测性、高并发流式网关能力以及容器化与自动化部署流水线，满足毕业设计答辩演示与生产环境稳定性要求。

### 3.2 后端与网关优化清单
1. **调用指标统计接口**：
   - 基于 `asset_invoke_log` 实现平台/域维度的汇总统计（总调用量、成功率、平均耗时）与近 7/30 天时间序列趋势（`GET /api/v1/stats/overview`、`GET /api/v1/stats/asset/:id/trend`）。
2. **SSE 流式调用透传**：
   - 完善 `/api/v1/invoke/mcp/:assetCode` 与 `/api/v1/invoke/agent/:assetCode` 的流式响应透传（`Flush` 实时输出）与异步审计落库。
3. **Nginx 网关调优（[ASCP_nginx.conf.example](file:///C:/Users/12907/Desktop/cur/docs/毕业设计/AI_Capability_Sharing_Platform/src/nginx/ASCP_nginx.conf.example)）**：
   - 验证 `upstream` 多后端实例负载均衡与故障摘除。
   - 验证 `limit_req_zone` 对认证与调用接口的突发限流效果，以及 SSE 路由 `proxy_buffering off` 无缓冲流式输出。

### 3.3 前端可视化清单（Vue 3 + ECharts）
1. **数据统计看板（`/analytics`）**：
   - 顶部核心指标卡（总资产数、总调用次数、平均成功率、平均响应耗时）。
   - ECharts 调用趋势折线图、四类资产分布饼图、Top 10 热门资产调用排行柱状图。
2. **能力广场在线调试沙箱**：
   - 在资产详情页提供“在线调试”窗口，支持实时发起调用并流式展示返回结果与耗时。

### 3.4 容器化与 CI/CD 流水线
1. **Docker Compose 一键编排验证**：
   - 验证 [docker-compose.dev.yml](file:///C:/Users/12907/Desktop/cur/docs/毕业设计/AI_Capability_Sharing_Platform/docker/docker-compose.dev.yml) 在本地一键拉起 `mysql`、`backend`、`frontend/nginx`。
2. **GitHub Actions CI/CD 流水线（`.github/workflows/ci-cd.yml`）**：
   - 自动执行 `go test ./...` 与 `npm run build` 验证代码质量。
   - 构建前后端 Docker 镜像并打 Git SHA Tag 推送至镜像仓库。
   - SSH 登录云服务器自动更新容器并探测 `/api/v1/healthz`，探测失败则自动回滚至上一稳定版本。

### 3.5 P2 验收标准
- 统计看板能准确展示平台调用趋势与资产排行图表。
- 通过 Nginx 统一入口可正常访问前端页面、代理后端 API 并触发限流保护与负载均衡分发。
- 提交代码后可触发 CI/CD 自动构建、单元测试与服务器部署，且本地与云服务器双环境均可稳定访问。
